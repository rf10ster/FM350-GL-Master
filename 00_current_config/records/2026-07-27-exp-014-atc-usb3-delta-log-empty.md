# Experiment Record: EXP-014 ATC ttyUSB3 Delta-Log Window (Empty Critical Slice)

## Metadata

- Experiment ID: EXP-014
- Date/time: 2026-07-27
- Operator: remote run from macOS via SSH one-liner
- Router: GL.iNet MT3000 (OpenWrt 24.10.7)
- Modem: FM350-GL via USB
- SIM/Operator: MegaFon
- Target AT port: `/dev/ttyUSB3`

## Objective

- Use line-delta extraction (`BASE=$(logread | wc -l)`) to capture only new logs generated by the current bounded run.
- Reduce historical contamination in diagnostics.

## Procedure

1. Measured log baseline line count (`BASE=1222`).
2. Applied profile:
   - `device='/dev/ttyUSB3'`
   - `apn='internet'`
   - `pdptype='IP'`
3. Presence pre-check passed (`presence=ok step=1`).
4. Enabled ATC with loop-breaker helper, waited 20s.
5. Captured status and filtered delta log:
   - `logread | tail -n +$((BASE+1)) | grep -E <critical patterns>`
6. Returned to safe-mode (`disable` + `status`).

## Results

- During attempt:
  - `up=false`
  - `pending=true`
  - `autostart=true`
- No IPv4 on `eth2`.
- Filtered delta critical log block was empty.
- After rollback:
  - `auto='0'`
  - `up=false`
  - `pending=false`
  - `autostart=false`

## Interpretation

- ATC still did not establish a session/IP, but selected critical patterns were not present in the captured delta slice.
- This can mean either:
  1. this particular attempt failed without known signature lines,
  2. pattern filter missed emitted lines,
  3. timing/log window did not include the relevant messages.

## Next Action

1. Capture unfiltered delta log to file first, then run pattern analysis on that file.
2. Keep safe-mode rollback mandatory after each bounded attempt.
